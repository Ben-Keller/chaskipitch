## Important caveats before merging

The `v4` pack is strong but should be merged as a supplemental layer, not blindly copied over live fields.

### 1) Status taxonomy mismatch

`v4` uses map labels (`active_project_country`, etc.), while live uses product statuses (`active`, `first_time_2024`, etc.).

- Safe map:
  - `active_project_country -> active`
  - `additional_projects_began_implementation_in_2024 -> additional_2024`
  - `projects_being_prepared -> preparing`
  - `under_assessment_for_future_projects -> under_assessment`
- Conflicts to keep live-truth unless validated against source workbook:
  - `BLZ`, `LBR`, `NPL` (live: `first_time_2024`, v4: `active_project_country`)
  - `COD` (live: `active`, v4: `additional_projects_began_implementation_in_2024`)

### 2) Narrative text quality issues

`v4` includes long excerpt-like titles and occasional footnote leakage.

Examples:

- Truncation markers (`…`) in many `project_descriptions.title`.
- Footnote-like titles (e.g., numeric prefixes) in some records.
- Cross-country phrase leakage in Panama source block (`From Papua to Panama...` and inferred Papua project link).

These should be cleaned in an ETL step before use in UI cards.

### 3) Project canonicalization is heuristic

`canonical_projects[]` and `project_or_initiative` are useful starting points, but not always safe to treat as final relational keys.

## Recommended merge approach

Use a dual-layer model:

1. Keep live country files as product-facing canonical records.
2. Ingest `v4` into a new supplemental evidence layer.
3. Derive curated fields into live schema only after rule-based normalization.

### Proposed data additions

1. `content/country-signals/<ISO3>.json`
   - normalized KPI atoms from `structured_kpis[]`
   - normalized narrative snippets from `project_descriptions[]` and `qualitative_highlights[]`
   - cleaned source excerpt references
2. Optional lightweight indexes:
   - `content/country-signals/index.json` (quick lookup by country/theme/metric family)

### Field mapping crosswalk

1. `v4.country_name -> live.name`
2. `v4.map_status -> live.status` via explicit mapping table (with per-country overrides)
3. `v4.theme_tags[] -> live thematics[]` via:
   - `tenure_security -> tenure-security`
   - `climate_biodiversity -> climate-biodiversity`
   - `mapping_monitoring -> technology-mapping`
   - `policy_advocacy -> policy-advocacy`
   - `women_gender_leadership -> women-youth-leadership`
   - `community_finance_livelihoods -> community-led-finance`
   - `institutional_context -> territorial-governance` (or keep as neutral editorial tag)
4. `v4.structured_kpis[] -> supplemental KPI atom model`
5. `v4.project_descriptions[] + qualitative_highlights[] -> story candidate pool`
6. `v4.source_trace[] -> source_refs enrichment`

## Merge sequence (safe)

1. Ingest
   - Parse v4 into `country-signals` without mutating live files.
2. Normalize
   - Apply status/theme/direction mappings.
   - Clean truncated/footnote titles.
   - Deduplicate KPI atoms (`metric + value + source_page + project slug`).
3. Reconcile
   - Link `project_or_initiative.slug` to live `projects[].project_id` through a lookup table.
4. Curate
   - Promote selected KPI atoms into `metrics` and thematic KPI cards.
   - Promote selected narrative blocks into `stories` and quote-style panels.
5. Validate
   - Extend QA script with checks:
     - no unknown theme tags
     - status mapping resolved
     - every promoted KPI has source page + unit + direction
